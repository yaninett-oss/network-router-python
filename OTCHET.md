**Дисциплина:** Компьютерные сети.

**Автор:** yaninett-oss

---

## 1. Цель работы

Освоить принципы взаимодействия нескольких сетевых клиентов через промежуточный узел — программный маршрутизатор.

В ходе работы создана модель компьютерной сети, включающая:

- несколько клиентов;
- несколько логических подсетей;
- программный маршрутизатор;
- TCP-соединения;
- UDP-соединения;
- обычных и приоритетных пользователей;
- таблицу маршрутизации.

## 3. Схема сети

```
                    ROUTER
              127.0.0.1:5000 (TCP)
              127.0.0.1:6000 (UDP)
                       │
       ┌───────────────┼───────────────┐
       │               │               │
       ▼               ▼               ▼
  ПОДСЕТЬ 1        ПОДСЕТЬ 2        ПОДСЕТЬ 3
  192.168.1.0/24   192.168.2.0/24   192.168.3.0/24
      TCP              UDP              TCP
       │                │               │
  ┌────┼────┐      ┌────┼────┐          │
  ▼    ▼    ▼      ▼    ▼    ▼          ▼
 C1   C2   C3     C4   C5   C6         C7
```

Подсети — логические. Все программы запускаются на одном компьютере, но каждому клиенту назначен логический IP-адрес, по которому маршрутизатор определяет его подсеть.

## 8. Как работает маршрутизатор

Алгоритм:

```
START
  │
  ▼
Получить сообщение
  │
  ▼
Определить отправителя
  │
  ▼
Определить получателя
  │
  ▼
Найти получателя в таблице
  │
  ├── Не найден → Ошибка
  │
  ▼
Определить подсеть отправителя
  │
  ▼
Определить подсеть получателя
  │
  ▼
Определить протоколы
  │
  ▼
Проверить приоритет
  │
  ▼
Передать сообщение
  │
  ▼
Вывести информацию
  │
  ▼
Продолжить ожидание
```
Маршрутизатор использует:

- **TCP-сокет** на `127.0.0.1:5000` — для TCP-подсетей;
- **UDP-сокет** на `127.0.0.1:6000` — для UDP-подсети;
- **threading** — каждый TCP-клиент обслуживается отдельным потоком;
- **json** — таблица клиентов читается из `clients.json`.

## 10. Формат сообщения

```
получатель|приоритет|текст
```

Пример:

```
Client5|HIGH|Привет!
```

Где:

- `Client5` — имя получателя;
- `HIGH` — приоритет (`HIGH` или `NORMAL`);
- `Привет!` — текст сообщения.

---

## 11. Приоритеты

В работе используются два уровня приоритета:

- `NORMAL` — обычное сообщение;
- `HIGH` — приоритетное сообщение.

Различия:

1. Если **пользователь** имеет приоритет `HIGH` (например, Client3, Client5, Client7), то все его сообщения **автоматически** помечаются как `HIGH`.
2. Приоритетные сообщения маршрутизатор пересылает **сразу**.
3. Обычные (`NORMAL`) сообщения пересылаются с **небольшой задержкой** (`time.sleep(1)`), чтобы визуально показать разницу.

## 13. Тестирование

### Тест 1. TCP → TCP внутри одной подсети

Client1 (TCP) → Client2 (TCP), оба в подсети 192.168.1.0/24.

Маршрутизатор выводит:

```
[ROUTER] ПОЛУЧЕНО СООБЩЕНИЕ
  Отправитель:        Client1 (192.168.1.10)
  Получатель:         Client2 (192.168.1.11)
  Подсеть отправителя: 192.168.1.0/24
  Подсеть получателя:  192.168.1.0/24
  Протокол отправителя: TCP
  Протокол получателя:  TCP
  Приоритет:           [NORMAL]
  Сообщение:           Привет!
```

### Тест 2. TCP → UDP между подсетями

Client1 (TCP, подсеть 1) → Client4 (UDP, подсеть 2).

Маршрутизатор выводит:

```
[ROUTER] Выполняется межсетевой маршрут.
[ROUTER] Выполняется преобразование протокола.
```

### Тест 3. UDP → TCP

Client4 (UDP) → Client1 (TCP).

Маршрутизатор снова выполняет межсетевой маршрут и преобразование протокола.

### Тест 4. Приоритетное сообщение

Client3 (TCP, HIGH) → Client5 (UDP, HIGH).

Маршрутизатор выводит:

```
[ROUTER] Приоритетное сообщение.
[ROUTER] Выполняется межсетевой маршрут.
[ROUTER] Выполняется преобразование протокола.
```

Сообщение отправляется без задержки.

### Тест 5. Неизвестный получатель

Client1 → Client999.

Маршрутизатор выводит:

```
[ROUTER] Получатель Client999 не найден.
```

Сообщение не пересылается.

### Тест 6. Отключённый клиент

Client1 → Client4, но Client4 уже завершил работу.

Маршрутизатор выводит:

```
[ROUTER] Клиент Client4 не подключён.
```

### Тест 7. Команды `/list` и `/stats`

Клиент отправляет `/list` — маршрутизатор выводит список подключённых.

Клиент отправляет `/stats` — маршрутизатор выводит статистику:

```
========== СТАТИСТИКА ==========
  TCP сообщений:      15
  UDP сообщений:      12
  HIGH:               8
  NORMAL:             19
  Внутри одной подсети: 14
  Межсетевых:         13
================================
```

## 15. Ответы на контрольные вопросы

1. **Что такое маршрутизатор?**
   Устройство или программа, которая принимает сетевые данные и определяет, куда их направить дальше.

2. **Чем маршрутизатор отличается от сервера?**
   Сервер обслуживает клиента напрямую. Маршрутизатор принимает данные и пересылает их другому узлу, анализируя адрес и маршрут.

3. **Что такое подсеть?**
   Логически выделенная часть сети с определённым диапазоном IP-адресов.

4. **Что означает запись 192.168.1.0/24?**
   Сеть с адресами 192.168.1.0 – 192.168.1.255, маска /24.

5. **Зачем разделять сеть на подсети?**
   Для логической организации, управления трафиком и изоляции.

6. **Что такое таблица маршрутизации?**
   Набор правил, определяющих, куда направлять трафик для той или иной сети.

7. **Зачем маршрутизатору информация о получателе?**
   Чтобы определить его подсеть, протокол и маршрут.

8. **Чем TCP отличается от UDP?**
   TCP устанавливает соединение и гарантирует доставку; UDP — без соединения, без гарантий, но быстрее.

9. **Что означает SOCK_STREAM?**
   Потоковый сокет — TCP.

10. **Что означает SOCK_DGRAM?**
    Датаграммный сокет — UDP.

11. **Для чего используется send()?**
    Отправка данных через TCP-соединение.

12. **Для чего используется sendto()?**
    Отправка UDP-датаграммы по указанному адресу.

13. **Для чего используется recv()?**
    Приём данных из TCP-соединения.

14. **Для чего используется recvfrom()?**
    Приём UDP-датаграммы вместе с адресом отправителя.

15. **Почему TCP требует установления соединения?**
    Чтобы обеспечить надёжность и порядок доставки.

16. **Почему UDP может отправлять данные без соединения?**
    Потому что UDP не гарантирует доставку и не устанавливает состояние соединения.

17. **Что такое многоклиентский сервер?**
    Сервер, обслуживающий несколько клиентов одновременно.

18. **Зачем используется threading?**
    Чтобы обслуживать несколько клиентов параллельно.

19. **Что такое поток выполнения?**
    Отдельная ветка выполнения внутри программы.

20. **Почему серверу нужно несколько потоков?**
    Чтобы не блокировать обработку одного клиента ожиданием другого.

21. **Что такое регистрация клиента?**
    Сообщение клиента маршрутизатору со своим именем (`REGISTER|ClientN`).

22. **Зачем маршрутизатору знать информацию о клиентах?**
    Чтобы определять подсеть, протокол и способ доставки.

23. **Что такое приоритет трафика?**
    Уровень важности сообщения.

24. **Чем приоритет пользователя отличается от приоритета сообщения?**
    Приоритет пользователя — постоянная характеристика; приоритет сообщения — характеристика конкретного сообщения.

25. **Что означает HIGH?**
    Высокий приоритет.

26. **Что означает NORMAL?**
    Обычный приоритет.

27. **Что такое межсетевой маршрут?**
    Передача сообщения из одной подсети в другую.

28. **Что происходит при передаче сообщения из одной подсети в другую?**
    Маршрутизатор определяет разные подсети и пересылает сообщение через соответствующий интерфейс.

29. **Может ли отправитель использовать TCP, а получатель UDP?**
    Да. В нашей модели маршрутизатор выполняет прикладное преобразование.

30. **Как маршрутизатор определяет получателя?**
    По имени, указанному в поле «получатель» сообщения.

31. **Что произойдёт, если получатель не зарегистрирован?**
    Маршрутизатор выведет сообщение «Получатель не найден».

32. **Что произойдёт, если получатель отключён?**
    Маршрутизатор выведет «Клиент не подключён».

33. **Для чего используется JSON в данной работе?**
    Для хранения таблицы клиентов отдельно от кода.

34. **Что хранится в clients.json?**
    Имя, IP, подсеть, протокол и приоритет каждого клиента.

35. **Для чего используется json.load()?**
Для чтения JSON-файла и преобразования его в объект Python.

36. **Зачем использовать отдельные функции для TCP и UDP?**
    Для разделения логики и упрощения поддержки.

37. **Что такое client_socket?**
    Сокет конкретного клиента.

38. **Чем клиентский сокет отличается от серверного?**
    Серверный ожидает подключения; клиентский обслуживает конкретное соединение.

39. **Почему необходимо закрывать сокеты?**
    Чтобы освободить ресурсы и корректно завершить соединение.

40. **Что происходит с сообщением при прохождении через маршрутизатор?**
    Оно принимается, анализируется, определяется маршрут, приоритет, протокол, и сообщение пересылается получателю.
